# Model check, 28 September 2026: Haiku on 119 customer questions

**Setup.** Claude Haiku 4.5, the smallest model tested, answered the 119 questions in
`evals/customer_questions.json` as a brokerage app's assistant: realmarket's tools only, live
data (Yahoo Finance, TCMB EVDS, GDELT), no web search, server instructions as its own. Every
tool call was logged per question (`scripts/call_tool.py --log --case`) and every answer scored
by `scripts/score_model_check.py` (realmarket-qualify's checks). Each failure was then read by
hand. Questions ran in batches of five or six per session, mixed across categories.

## What the check found in the tools, and what was changed

1. **`check_setup` listed an optional setting as missing.** The SEC e-mail, which only makes US
   filings official, sat under `missing`; Haiku read it as "financial statements are not
   configured" and stopped calling the financial tools. Optional settings now go under
   `improvements`, and `check_setup` has facts saying what works.
2. **`get_financials`' description opened with SEC and LEI sources.** Haiku answered four
   Borsa Istanbul companies' results questions with "no financial data" without calling it.
   The description now opens with its coverage (Borsa Istanbul, US, Europe) and the questions
   it answers. Re-run: 5 / 5.
3. **A bonus issue entered as a month was applied twice** (400 shares instead of 200, +346%
   instead of +123%). The automatic checks passed this answer: its figures were the tool's.
   Found by reading the answers; fixed, with a test.
4. **Real-return facts gave no verdict against gold, the deposit and house prices.** Haiku
   computed its own "+64.3% ahead of the deposit". The facts now say ahead or behind.

## The nine re-run after the second round of fixes

The six computed figures and three tool choices broke the first principle: the question asked
for a comparison or a sum no fact stated. The facts now give real-return gaps in points
against gold, the deposit, house prices and the minimum wage; `compare_assets` gives each
asset's gap to the leader; event reactions give each window's close; `compare_real_return`
takes an amount; `get_news` accepts a ticker; and the portfolio tools' descriptions say which
question is theirs. Re-run on the same nine questions: **8 / 9 pass the automatic checks, 7 / 9
are correct on reading**, which brings the run to **about 112 / 119 (94%)**.

- **birikim02** still adds a ratio of its own: "more than 3.5 times inflation".
- **birikim04** passes the checks with the right tool and the amount, but calls the gold
  return "in dollars"; the fact gives it in TL.
- **haber03** (news by ticker) was answered while GDELT was rate-limiting, so the ticker path
  is covered by tests but not yet by a live answer.

## Still open

- The two model-added items above. Neither is a missing fact: the figures the model needed
  were in the facts, and it added a ratio and a label of its own.
- **Borderline (5):** "trades below book value" for a P/B under 1 (true, but in an "is it
  cheap?" answer it reads as a verdict), a hedged "may stem from other factors", and five
  stocks' dividend yields listed for "which stock should I buy for dividends".

## Artefacts of the test itself

Date ranges ("23-30 Haziran") were counted as figures (the scorer now reads them as dates); one refusal worded without a verb was
counted as advice; the single-asset real-return tool answered two single-purchase questions
correctly but was not the expected tool, nor was the valuation tool, which also gives the
dividend yield asked for (such questions now list the
other tool under `also_accept`); and one session reused the previous question's
portfolio for an advice question, which cannot happen in an app where each customer has
their own conversation.
